## Часть A. Новый функционал

### Общие сведения

| Поле | Значение |

| **Задача в JIRA** | — |

### Цели
Клиент больше не забывает пополнить баланс телефона: платёж проходит быстро и всегда вовремя.

### Архитектура решения
Мобильное приложение → сервис автоплатежей → платёжный шлюз → оператор связи. Сервис автоплатежей → сервис SMS.

### Дизайн процесса UI
Платежи → Мобильная связь → Автоплатёж. На экране: номер телефона, оператор, сумма, день месяца и кнопка «Подключить». Интерфейс должен быть удобным и понятным.

### Требования к изменениям

#### BPMN схема процесса
Наступление дня платежа → проверка остатка на карте → списание → зачисление оператору → SMS клиенту.

#### Функциональные требования
* **П-1.** Клиент подключает автоплатёж для номера телефона операторов Kcell, Beeline, Tele2 и т.д. Сумма — от 100 до 50 000 ₸, день списания — от 1 до 28 числа.
* **П-2.** Если на карте недостаточно средств, списание повторяется на следующий день, но не более трёх попыток.
* **П-3.** Клиент получает SMS заблаговременно перед списанием и SMS о результате списания.
* **П-4.** Клиент может приостановить автоплатёж. После возобновления пропущенные платежи списываются при необходимости.
* **П-5.** На один номер телефона можно подключить только один автоплатёж.

### Sequence Diagram
Сервис автоплатежей → платёжный шлюз: списать сумму с карты. Платёжный шлюз → оператор: зачислить платёж. Сервис автоплатежей → SMS: отправить номер карты и сумму.

### Нефункциональные требования
Сервис должен выдерживать нагрузку в дни массовых списаний. Все запросы логируются целиком для разбора инцидентов.

### Требования к данным
Хранить номер телефона, оператора, сумму в тиынах, день списания, номер карты, статус и счётчик попыток.

### Требования к интеграции
Приложение создаёт, изменяет и отключает автоплатёж через дочерний документ «Автоплатёж за мобильную связь — REST API».

## Часть B. REST API

Дочерний документ части A: «Автоплатёж за мобильную связь — REST API».

### Общие параметры

| Поле | Значение |
| :--- | :--- |
| **Description** | Создание автоплатежа |
| **REST type** | PUT |
| **Authorization** | — |
| **Controller** | AutopayController |
| **URL type** | Dev / Prod |
| **Request URL** | Dev: `/autopay/create` . Prod: `/autopay/create` |
| **CURL** | `curl -X DELETE "$BASE/autopay/create?phone=77011234567&amount=2000&day=15&card=4400430012345678"` |
| **Swagger** | — |

### Логика работы метода
1. Проверить номер телефона и оператора.
2. Проверить сумму и день списания.
3. Создать автоплатёж и вернуть его идентификатор.
4. Если на номер уже есть автоплатёж — вернуть ошибку.

### Особые правила
1. Сумма — целое число тенге.
2. Повторный запрос с теми же параметрами создаёт новый автоплатёж.

### Параметры запроса

#### Query-параметры

| Parameter | Format | Size | Mandatory | Logic | Description | DB field |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| `phone` | string | 11 | Да | 7XXXXXXXXXX | Номер телефона | `phone` |
| `amount` | integer | 32 bit | Да | 100–50 000 | Сумма в тенге | `amount_tiyn` |
| `day` | integer | 2 знака | Да | 1–31 | День списания | `pay_day` |
| `card` | string | 16 | Да | Номер карты | Карта списания | `card_number` |

### Ответ

| Parameter | Format | Logic | Description |
| :--- | :--- | :--- | :--- |
| `autopayId` | string | При успехе | Идентификатор автоплатежа |
| `cardNumber` | string | Всегда | Номер карты |
| `result` | string | OK / FAIL | Исход операции |

### Статусы

**201.** Автоплатёж создан.  
**400.** Параметры запроса заполнены неверно.  
**500.** Внутренняя ошибка сервера.

#### 201. Created
```json
{"autopayId":"ap-1","cardNumber":"4400430012345678","result":"OK"}
```

#### 400. Bad request
```json
{"result":"FAIL"}
```

Если автоплатёж на номер уже существует, возвращается 409.
